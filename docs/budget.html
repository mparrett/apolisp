The budget has never said no

apolisp has a hard line budget: 7,500 lines for the language, comments and blank lines included. The test that enforces it fires a thousand lines late, on purpose, so that nobody can argue about forty. In ten milestones it has refused nothing — and three separate times it quietly stopped measuring the thing it exists to measure. A fourth turned up while writing this page.

6,845 of 7,500/asserted at 8,500/0 refusals/3 silent failures in the log, 1 found here

−20% By accident Counting comments against a number set without them was a fifth of the budget removed by nobody’s decision.
4 Milestones unbudgeted A whole layer had no row and nothing said so, because only the total is asserted.
439 Lines outside An exclusion by directory is a way to move lines out of a budget by moving files. Now it prints.
What it is

A context-window constraint, so a comment costs what code costs

Constraint #1 in the project’s ethos is not an aesthetic preference:

Legibility budget. The entire core is holdable at once — by one engineer and by one language model. This is a context-window constraint, not an aesthetic one, and it is the binding constraint on every other decision.

That framing decides the counting rule. If the thing being measured is how much has to be held at once, then a comment occupies the window exactly as code does, and counting code alone would make the number stop measuring the constraint it exists for. So the unit is lines of file, blanks included. prelude.xs counts too — it is not Rust, but def and defmacro are defined in it, so it is core language.

The check prints before it asserts, and the printout is the part that does the work:

The last row is a different matter. 550 lines, 8% of the core, belong to no budgeted layer at all: the process driver, the prelude, and the stub above the first mod. The table has never had a row for any of them, and nothing reports it, because only the total is asserted and a total does not know which rows it is made of.

Keep that sentence. It is about to happen twice more.

The design

The number is imprecise on purpose, and the test fires late on purpose

The entry that fixed the counting rule made a second decision that matters more: the budget is an order of magnitude, not a threshold.

Whether the core is 5,000 lines or 7,000 does not change whether one engineer and one model can hold it; whether it is 7,000 or 70,000 decides it. Precision past the nearest thousand is false, and a budget that reads as exact invites arguing about 40 lines instead of noticing a subsystem that doubled.

±1,000 is inside the noise band. Only the total is asserted; the per-layer rows are printed and never enforced, because a hard check at 300-line granularity would be false precision and would generate churn for rebalancing that carries no meaning.

And then the move that makes it real. The constant in the test is not the budget:

█filled to 6,845, the core today ┊dashed at the 7,500 budget │the bar ends at the 8,500 assertion

The tripwire sits at the top of the noise band rather than at the working number, because failing at 7,001 would invite exactly the 40-line debate the entry exists to prevent.

This is a constraint deliberately built so that it cannot be won by argument. There is no version of “we are only slightly over” available, because slightly over does not fail; and by the time it does fail, the conversation is not about forty lines. The cost is stated plainly rather than hidden: a budget with 1,000 lines of slack cannot catch anything small, and a bloated layer can hide inside a lean one.

The question a row answers is “did this subsystem double,” never “is this 40 lines over.”

Which means the test is not the instrument. The instrument is the printed report, and the test exists mainly to make sure the report gets printed.

Silent failure one

A fifth of the budget went missing without anyone deciding

The project started from a figure of 3,000–5,000 lines, inherited from the design conversation that preceded it. That figure assumed minimal comments. Then the counting rule said comments count.

Nobody made that decision. Milestone 1 measured 19% comments and blanks, so applying the new rule to the old number was a silent ~20% cut — and it taxed exactly the why-comments that make the core holdable in the first place. The fix was to state the counting rule out loud and restore the headroom the layer table had always meant, which is how the total became ~7,000.

The shape of it

A rule and a number that were each defensible produced, in combination, a fifth of a governing constraint disappearing. Neither half was wrong. Nobody chose the result, and nothing would have reported it — the suite is green either way, because a budget nobody is near does not fail when it shrinks.

And the number that raise was sized on

19% was right when it was measured, and it is 27% now

The raise was justified by a measurement, and the measurement has moved. Counting lines that begin with a comment marker, plus blanks, across the three files the budget covers:

At milestone 1’s 19%, a 6,845-line core would carry about 1,300 lines of comment and blank. It carries 1,827. The difference is roughly 525 lines — 7% of the budget — absorbed with nothing reporting it, because only the total is asserted and the total is nowhere near its tripwire.

The entry predicted this in as many words: “denser subsystems will run higher”. It was right. What a budget of this design cannot do is notice by how much, or ask whether the raise it sized on 19% is still the right raise at 27%.

The prelude is the sharpest case at half comment, and it is the same finding two pre-registrations already ran into from the other direction: twice, a change predicted to make the code smaller made the file bigger, because the comment explaining a subtle invariant outweighed the code it replaced. The prelude went 195 → 201 on a change whose entire point was deleting two loops. Estimating the code is not estimating the change — and under this counting rule, the explanation is charged at full price.

Which is the intended trade, stated honestly

The alternative was rejected for a stated reason: a tighter budget with comments counted “taxes exactly the why-comments that make the core holdable”. That tax exists at any ceiling. Raising the ceiling did not remove it; it moved where it bites, and 27% is where it bites now.

Silent failure two

A layer nobody had budgeted, for four milestones

The layer table was written before serialization existed as a subsystem. Then ADR-029 invented the Vm/Execution/Image split, and the entry that raised the total to ~7,000 raised it without noticing that the new layer had no row.

So fuel, Image and resume were unbudgeted from the moment they were invented until four milestones later — and nothing said so, because only the total is asserted and the total does not know which layers it is made of.

What fixed it is worth more than the fix. The row was written before the code, and the entry says exactly why:

The difference between deciding 500 now and recording 500 afterwards is the difference between a budget and a measurement.

A number filled in after the work is not a constraint that shaped the work; it is a description of what happened, wearing a constraint’s clothes. Every layer row added retroactively would have been that. This one was 500 against ~1,200 uncommitted lines, chosen while it could still be wrong — and it came in at 416.

Silent failure three

An exclusion that describes an empty set costs nothing until it doesn’t

The build document has said host adapters are outside the line budget since before any adapter existed. For most of the project that sentence was free, because it described an empty set.

Milestone 10 gave it content: a terminal, TCP, and JSON, 439 lines across four files. And a sentence that used to be a scoping note became something else.

The moment it describes real files it becomes a way to move lines out of a budget by moving them into a directory, and the only defence is that the move is visible on every run.

So the exclusion prints, itemized, with line counts, on every run of the check — the block at the bottom of the report at the top of this page. An exclusion nobody can see is how a budget stops measuring anything, and the defence is not a rule against moving files. It is that moving one is loud.

The inversion worth noticing

The same exclusion became an argument for taking two dependencies. Hand-writing JSON escaping and terminal capability detection would have added several hundred lines of protocol nobody reviews carefully — outside the budget, so nothing would even flag the growth. A boundary drawn to protect the language turns out to be, on its far side, the place where growth is invisible.

The boundary is still the right one, and it is drawn on a principle rather than on convenience: substantial host capability is a Rust library behind the handle table, not a language subsystem. But “outside the budget” and “unmeasured” are not the same thing, and only one of them was intended.

The accounting

In ten milestones it has refused nothing

Here is the part that a page about a line budget is most tempted to leave out. Searching every entry in the decision log: no decision has been declined with the line budget as the deciding reason.

0features refused
0test failures
2raises, both by ADR
655lines of headroom

The one place the budget appears as an explicit gate is the optimisation ladder, whose middle tier — large but self-contained, e.g. tiered collections at about 1,200 lines — is gated on it. That tier has never been reached. The budget has been raised twice, both times by an entry that said what grew and why, which is its own rule working; it has never once been the thing that stopped something.

A constraint that never binds is doing one of two things: the work genuinely fits, or the constraint is slack. Both are true here. 6,845 against a 7,500 target and an 8,500 assertion is a quarter of the artifact in room.

So what did it buy? Not refusals. It made every growth event a written decision with a number attached. Entries carry their cost in lines as a matter of course — core goes from 6,303 to 6,561, 6,561 to 6,616 — 55 lines, against the 25–35 predicted, 6,616 to 6,637; prelude 195 → 201, which is longer. None of that would exist without a number to state the cost against, and it is the record that makes a pre-registration’s line prediction scoreable at all.

The honest claim

The budget has not kept the core small. Nothing has yet wanted to make it large. What the budget did was make the size of every change a thing somebody wrote down at the time — which is the only reason it is possible, ten milestones in, to say where the lines went rather than guess.

The pattern

Three failures, one shape

The silent cut, the unbudgeted layer, and the free exclusion are not three unrelated mistakes. Each is the same thing: the budget went on passing while it stopped measuring what it exists to measure.

  • The cut changed what the number means, and the assertion could not tell, because a total does not know what rule produced it.
  • The unbudgeted layer changed what the number covers, and the assertion could not tell, because a total does not know which layers it is made of.
  • The exclusion changed what the number sees, and the assertion could not tell, because a total does not know which files were skipped.
  • The 550 unrowed lines are the same defect standing still rather than moving — a partition that never covered the artifact. Those three are in the decision log. This one is not: it turned up while laying the printed report against the budget table to make the comparison above, which is the first time in ten milestones anyone had done that.

In all four the test was correct and green throughout. That is the same defect this project keeps finding elsewhere under a different name: a true assertion applied to a subject that quietly moved, where review reads the assertion and nothing reads the subject. A budget check is just an assertion whose subject is a set of files, and a set of files is exactly the kind of subject that drifts.

The response was the same each time, and it is the only one that has worked: make the subject print. The counting rule is stated in the entry, the per-layer numbers print, and the exclusion prints with its line counts. None of those is an assertion. All three exist so that a person reading the output can see what the number was computed over — which is the check that actually caught all three.
