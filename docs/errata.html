The decision was right and the reason was wrong

apolisp keeps an append-only decision log: 55 entries, and the only edit a past entry ever receives is a one-line pointer. Four have been superseded. Seventeen carry a factual correction — because what turns out to be wrong in a decision record is almost never the decision.

The mechanism

One file, appended to, with exactly one editable line

The rule is stated in the log itself, as an entry about the log:

To change a decision, add a new entry that supersedes the old one and add a Superseded by ADR-NNN line to the old entry — that line is the only edit a past entry ever receives. No version bumps, no amendment procedure, no approval step.

The reasoning is about what the log is for. This is a project with one user and an explicit freedom clause: the language may break on a Tuesday and be rebuilt on Wednesday, and that costs nothing. What is not free is silently losing why Monday’s version existed — that costs a re-derivation every time the question resurfaces, and the re-derivation is usually worse than the original because the pressure that produced it is gone.

Supersession keeps that trail without acquiring a governance process. The rejected alternatives are named: a decisions/NNN-*.md directory (more files than decisions, and a directory walk to answer anything spanning two of them), amending entries in place (loses the trail, which is the only thing the log is for), and version bumps (governance language written for a language with users, of which there are none).

But supersession is a heavy instrument. It is for a decision that changed. It is the wrong tool for an entry whose decision is fine and whose third paragraph contains a false sentence — and that turns out to be the common case by a factor of four.

Why correct a reason at all

The reason is what gets reused

The errata section opens with its own justification, and it is the whole argument in three lines:

Factual corrections to entries whose decision still stands. A wrong reason is worth fixing even when it reaches the right conclusion, because the reason is what gets reused. Superseding an entry over a mistaken sentence would be ceremony; errata are the cheaper mechanism, and the affected entry carries a pointer line. Where a correction changes a decision, it gets an ADR instead.

The first erratum filed is the clearest case. ADR-019 chose to ship the VM as a wasm module with values in linear memory rather than compiling the language to WasmGC, and gave as its reason that WasmGC “puts frames back on the wasm stack and forfeits constraint #2” — the constraint that a running computation stays plain data, suspendable and serializable.

That is simply false. WasmGC provides managed struct and array references; an interpreter can hold explicit frames in GC-managed arrays exactly as it can in linear memory. Linear memory stands as the decision, on entirely different grounds: Rust toolchain support, control over layout, ease of producing a canonical byte-oriented image, and not depending on host GC behaviour.

Leave the false reason standing and it is what a future reader picks up. It generalises so nicely — managed runtime, therefore no explicit stack, therefore no snapshot — that it would get applied to the next three targets without anyone re-checking it. The conclusion was never in danger. The sentence underneath it was load-bearing for everything that came after.

The kinds

Five things that go wrong in a decision record, none of which is the decision

E-3

A reason that was never load-bearing

“TinyGo drags in Asyncify” is too categorical — TinyGo uses it for goroutines on wasm, and its scheduler can be disabled. The decision stands because Rust is the working toolchain and the legibility argument is independent. This was never the reason it rested on, and stating it as though it were invites someone to defend it.

E-4, E-6

A number nobody measured, written as if measured

“~30% more lines than Go” is a projection; no comparable pair has been built. “Transducers are faster” is inherited folklore, not something measured on this implementation. Both read like evidence and neither is.

E-8, E-9

A code sketch that could not survive being implemented

The predicted 24-byte Value measured 16, because the sketch assumed Rc<str> and Rc<[T]> — fat pointers — and the implementation uses thin pointers to sized structs. Worse, ADR-026’s carrier sketch reads LocatedForm { root, origin }, one origin, directly alongside prose saying “every aggregate holds one origin per syntactic child”. Those cannot both be one struct. The prose survived two reviews; the code block did not survive first contact.

E-14

A cost predicted and never paid

ADR-043 warned that preserving structural sharing would make decoding two passes rather than one, because an object could name an id it had not reached yet. Written before the encoder was. The encoder builds an object’s children before pushing the object itself, so every id is strictly lower than its own, the table comes out topologically ordered by construction, and the decoder is a single forward loop with no fixups. Sharing cost a map on the encode side and nothing at all on the decode side.

E-13

A win claimed in the present tense that has not arrived

The one below, which is the sharpest of the seventeen because it was settled by measurement rather than by argument.

Two more that do not fit the pattern but are worth having: E-7 corrects a word (“hygiene” overstates what read-time resolution plus gensym provides — read it as Clojure-style capture avoidance), and E-10 corrects a claim the log made about itself — a split described as the second step of a stated progression is the third, because the intermediate step was skipped rather than taken.

E-13

The optimisation that was indistinguishable from not having it

ADR-041 chose flat vectors with copy-on-write and no transients. Its reasoning said Rc::make_mut removes the obvious cost — a fresh accumulator has one reference, so the loop mutates a buffer it already owns.

Measured, it never does. At a native call the collection is live in the caller’s argument window and in the clone the primitive takes, so the strong count is at least two and make_mut copies every time. In a conj loop the accumulator is additionally still bound to a live local. Instrumenting conj over a five-element build printed copied=true on every iteration.

And then the part that makes it a finding

Replacing make_mut with an unconditional clone survived the entire suite. The two are indistinguishable today — which means the claim in the entry was not merely optimistic, it was unobservable.

That is a mutation, run by hand and long before there was a harness for running them. The habit that later became mutate.sh shows up here first, aimed at a sentence in a document rather than at a line of code.

The decision stands unchanged: flat Vec, copy-on-write, no transients is still the right shape, and make_mut is still the correct way to write it. What is wrong is the tense. The quadratic behaviour the open question named is still there, and removing it needs either a compiler pass that kills a slot on its last use or a call protocol where a primitive consumes its arguments — both pre-registered as experiments, neither a collections question.

One win is real, and the erratum says so rather than retreating entirely: a multi-pair assoc or multi-item conj copies once rather than once per pair, because the mutable borrow is taken outside the loop.

The recursion

An erratum is a claim like any other, and nothing tests it

Two of the seventeen correct earlier errata. That is not a defect in the mechanism; it is the mechanism working on itself. But each one arrived for a different reason, and the reasons are the useful part.

ADR-034A finally body is duplicated, so the code array doubles under nesting.
↓
E-12Adds: the proto table doubles with it, which is a size statement rather than a correctness one. And it matters because Chunk.protos is what an Image serializes, so the duplication reaches the snapshot.
↓
E-15True when written, false since ADR-043: an Image carries a chunk fingerprint and takes the chunk from its caller. No Chunk is serialized at all. The duplication reaches the compiler’s output and stops there.

E-12’s substance is untouched — the proto table really does double, and that is a size statement rather than a correctness one. What went stale is the consequence, and E-15 says plainly why that is worth more than the correction:

ADR-043 changed what an Image contains, and nothing walked the errata to see what had been asserted about it.

A decision record has a status line and a supersession trail. An erratum has neither. It is a free-floating factual claim about a system that keeps moving, and there is no test anywhere that fails when one of them stops being true. This one was caught by a person reading; that is the entire mechanism, and it is worth being honest that it does not scale.

E-17

The erratum that abolishes its own category

The second chain is shorter and ends better. ADR-055 created the mutation harness and its cost clause said “eight mutations, seven flipping”. E-16 corrected that to eighteen. E-16 was stale within the day.

ADR-055Cost: eight mutations, seven flip, one survives as declared.
↓
E-16The set is eighteen, seventeen flipping. The decision stands unchanged; only the inventory moved.
↓
E-17Both entries state an inventory in prose, which guarantees a correction per sitting and teaches nobody anything. mutate.sh is the count. Neither number should be read as current, and no further erratum will be filed to move one.

The set is forty-five now, which is exactly the point: that sentence is already the wrong kind of sentence to have written, and it is safe here only because this page is a description rather than a record anything defers to.

E-17 does something the other sixteen do not. Rather than correct a fact, it withdraws a kind of fact from the log — and gives the reason in terms of what the log is for. An entry exists to carry reasoning that would otherwise be re-derived badly. A count of things in a file is not reasoning; it is a cache of something the file already knows, and a cache with no invalidation is a bug wearing documentation’s clothes.

What E-17 keeps instead is the part a file cannot hold: not how many mutations there are, but that milestone 8’s ten found one hole and confirmed nine — including all four survivors from its original pass, which had been closed by adding programs, so the rung now guards those programs against removal. And that milestone 5’s five found nothing, which is the first pass where nothing was wrong and is worth recording as such.

The rule that falls out

Do not write a number into prose when an artifact already holds it. Point at the artifact. The corollary is uncomfortable and correct: every inventory, every count, and every “currently N” in a document you are not going to re-read is a correction you have already scheduled.

Seventeen corrections against four reversals. The ratio is the finding: a decision that took real thought tends to survive, and the material around it — the numbers quoted, the sketches, the costs projected, the reasons that sounded general — is where the errors live. A log that could only supersede would have recorded none of this, because none of it was ever grounds for changing course.
